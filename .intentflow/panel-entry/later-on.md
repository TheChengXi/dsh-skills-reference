# later-on：后续想法备忘

> 设计阶段识别但**此时不做**的事项，以及未来可能的演进方向。只记录想法，不做任何设计预留——需要时直接实现。

## 想法列表

- **L01**：hero 态（新会话首屏）常驻入口
  - 现状：入口挂在 `conversation.input.left`，该 slot 只在选中会话时挂载，新会话首屏看不到入口 —— 这是 DSH「工具行属会话内控件区」的既定语义，本轮已确认接受。
  - 何时做：用户提出「还没选会话就想先配引用」时。
  - 备注：届时不要往工具行硬塞，应另找常驻 slot（如 `shell.overlay` 的轻量触发器），避免出现两个视觉入口。

- **L02**：入口按钮图标化（纯图标 + tooltip）
  - 现状：纯文字「skill」，工具行横向尚有空间。
  - 何时做：工具行新增其它控件、文字标签开始挤压同行控件时。
  - 备注：图标需内联 SVG 手写 path（受决策5 约束，不能用 DSH primitives 的图标组件）。

- **L03**：hover / 焦点反馈改用真实伪类
  - 现状：按决策1 用内联样式 + React state 近似 hover，键盘焦点走浏览器默认 focus ring，与原生权限选择器自绘的焦点环形状不同。
  - 何时做：需要对原生控件做像素级对齐，或入口按钮的交互态继续增多（active / disabled / busy）时。
  - 备注：届时推翻决策1，改为注入 `<style>` 标签 + 类名（DSH 官方插件做法），并把既有内联样式一并迁走，避免两套机制并存。

- **L04**：入口按钮承载引用源健康状态
  - 现状：逐源健康度只在面板内呈现，入口按钮是无状态文字。
  - 何时做：出现「引用源失效但用户没打开面板、因此不知情」的真实反馈时。
  - 备注：可在按钮上加状态角标（沿用 `--dsw-alias-state-error-primary` 等语义 token），数据源复用既有 `remote.inspect`，不新增宿主能力。

## 与当前设计的关系

L01 与 L03 都可能改动「面板展示层」的组件边界（前者新增常驻触发器组件、后者迁移样式机制），当前不做预留：`ComposerEntryButton` 保持单一职责（打开面板），样式机制保持内联一套。届时应直接重构，而非在本轮预留扩展点。
