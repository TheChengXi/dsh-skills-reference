# skill-enablement 关账报告

## 1. 项目概览

给引用源 skill 增加「单 skill 粒度启停（白名单）」：声明条目新增 `skills` 白名单字段并在**宿主侧真实生效**（不在白名单的 skill 不进 catalog，同名的本地 skill 按下位规则回退），面板预览区重构为逐 skill 卡片并提供官方规格的启停开关，开关改动进入既有编辑态（保存才落盘、取消即回滚）。

## 3. 关键决策

- **新增真实 FS 端到端测试（修正设计事实）**：design 的测试策略写「保留既有真实 FS 用例」，经核实**不成立**——既有测试全部使用假内层实例。遂新增 `test/skill-enablement.test.ts`，并同步修正 `design.md` 的测试策略与改动点清单。
- **视觉层级重排（超出 design 范围，用户反馈驱动）**：容器 `bg-layer-3 → bg-layer-1`、卡片 `bg-layer-1 → bg-module-platform`。依据是查证官方 token 两色板取值后发现：浅色下 `bg-base` 与 `bg-layer-1/2/3` **同为 `#fff`**，layer 序号给不出层级；且原组合在深色下让卡片（`#232324`）比其容器（`#353638`）更暗，凹凸语义相反。
- **取消停用项整卡 `opacity: 0.4`（用户要求）**：改为仅名称与描述取 `label-dimmed`，卡片底色与启用态一致。
- **启用态改为编辑态派生（`isSkillEnabled`）**：原设计让卡片读 inspect 快照的 `enabled`，导致点击开关无任何视觉反馈、必须保存后才变。改为由编辑态白名单派生（纯函数），点击即变、取消即回滚。列表顺序仍不即时重排——聚合顺序属宿主 `source-inspection` 职责，需 wire 变更（即 later-on L03）。
- **用户撤回「字体颜色改为系统色」的追加需求**：用户确认颜色已正常，该追加项未实施。

## 4. 经验记录

- **有效做法**
  - 白名单判定单点实现（`isSkillAllowed`）供 provider 与 inspection 共用，杜绝「面板显示停用但模型仍能加载」的漂移。
  - 候选归属用「逐源内层实例 + owner map」而非路径前缀推断——源目录可互相嵌套，前缀匹配会误判。
  - 视觉问题先查官方 token 在两色板下的**真实取值**再动手，本轮正是靠取值发现「浅色 layer 无层级差」这一决定性事实。
  - 真实 FS 端到端用例覆盖了假内层测不到的组合行为（逐源实例 + 白名单 + `get` 委派）。
- **踩坑**
  - **重构遗漏持有者**：把「1 实例多目录」改为「多实例单目录」时，内层实例的持有者有 `ensure`/`dispose`/`onReferencesChanged` **三处**，只改了两处，导致源变更不再释放旧实例；靠 dispose 次数断言才抓到。
  - **客户端状态源不一致**：卡片直接读服务端快照字段，编辑态改动自然不反映。结论：编辑态投影应由派生函数算出，而不是把快照就地双写（双写还会让「取消」无法回滚）。
  - **设计文档中的未核实假设**：引用「既有测试/既有行为」前必须先核实，否则错误会一路带到 execute 阶段。
- **工具反馈**
  - `tsx`/esbuild 在受限沙箱下 spawn EPERM（禁止命名管道）；本轮改用 `danger-full-access` 执行测试与构建。
  - 用户明确反馈「别一直跑测试」——改动期间反复跑全套测试属资源浪费。

## 6. 开发工作流反馈

- **execute 的验证节奏需要规则化**：本轮每改一个小项就跑全套测试、并做三次稳定性循环，用户指出浪费资源。建议 skill 明确：改动期间不跑测试，只在交付节点跑一次；稳定性循环仅在涉及并发/文件系统/时序时执行。
- **design 引用既有事实时应强制核实**：本轮 design 的测试策略写错了一处（「既有真实 FS 用例」并不存在），到 execute 阶段才被发现。建议 design 阶段对「沿用既有 X」的表述加一道核实动作。
- **视觉类需求缺少可验证手段**：agent 无法目视 GUI，只能靠 token 取值推导 + 用户复核，两轮颜色返工均源于此。建议对视觉项显式标注「需人工目视」，并把 token 两色板取值查证前置到 design。
- **关账入口时机**：`/report` 触发后随即插入了新的执行缺陷（开关无即时反馈），说明「关账」需要一个明确的封版点，否则报告写入即定稿的规则会与后续改动冲突。

## 7. 结论

- **当前状态**：可发布（58 测试全绿、`tsc` 与构建通过、用户确认视觉正常）。
- **建议下一步**：提交入库；如需可在 GUI 补一次功能步骤确认。L03（编辑态即时重排）留待用户提出时实现。
