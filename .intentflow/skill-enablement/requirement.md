# 需求文档：skill 引用启停（skill-enablement）

## 项目意图

让面板预览区里「来自引用源的每个 skill」可**单独启停**——关闭即把该 skill 真正移出目标工作区的 skill catalog（写回声明条目的 `skills` 白名单），并把预览列表重构为「来源标签前置的卡片 + 右侧常显开关」，关闭项灰显、描述限两行，消除当前线性堆叠列表的层级混乱与重复噪音。

## 功能清单

1. **单 skill 引用启停（白名单真生效）**：引用源的每个 skill 可逐个关闭/打开，关闭写入声明条目 `skills` 白名单，provider 与 inspect 同步过滤。
2. **停用状态承载与灰显**：关闭后该卡片整体降透明度、描述文本变灰，**仍保留在列表中可见**，暗示「在当前上下文被排除」。
3. **预览卡片信息层级重构**：来源标签前置、逐 skill 卡片化、描述最多两行超出省略、移除重复罗列 skill 名的 tag 行。
4. **开关呈现**：卡片最右侧常显 Switch（开=高亮、关=灰色），按官方 Switch 规格与官方 token 实现。
5. **本地同名回退**：被停用的引用源不再提供该 skill 后，本地同名 skill 按既有 rank 规则自然生效。

## 核心功能

### 核心功能1：单 skill 引用启停（白名单真生效）

- **能力**：系统能够 + 把引用声明条目从「目录级」扩展为「目录级 + 可选 `skills` 白名单」，并在 skill 发现链路（reference-provider）与只读巡检（source-inspection）两处**用同一份白名单语义**过滤，使被关闭的 skill 真正不再出现在目标工作区的 skill catalog 中。
- **业务价值**：直接回应「只想引用源目录里部分 skill」——用户不必为了排除一个 skill 而放弃整个源，也不必去改源工作区目录结构；排除动作在引用方本地、可逆、可声明化（写入文件、可评审、可版本管理）。
- **异常处理**：白名单里出现源目录中不存在的 skill 名 → 忽略，不报错、不阻断其余 skill；声明文件里 `skills` 不是字符串数组 → 与既有 `name`/`path` 校验一致地抛类型错误，面板提示解析失败。

### 核心功能2：预览卡片信息层级重构（承载开关）

- **能力**：系统能够 + 把预览区从「`名称 — 一长串描述 · 来源`」的线性列表重构为逐 skill 卡片：**来源标签前置**（第一视觉位，本地 skill 显示「本地」）、skill 名称居次、描述最多两行超出省略号、开关固定在卡片右侧；关闭项整卡降透明度（opacity 0.4）且描述与标签一并弱化。
- **业务价值**：用户扫列表时先分辨「来自哪个源」，再决定关哪个——信息前置与来源分组把开关的决策依据（来源）放在决策控件（开关）之前，配合置灰形成「哪些未生效」的一眼可读。
- **异常处理**：描述为空或超长 → 空描述不渲染描述块，超长按两行省略，卡片高度保持稳定，不撑破窗口。

## 业务规则

### 白名单语义

- **场景**：声明条目是否设置 `skills`。
- **行为**：条目形如 `{ name, path, skills? }`；`skills` **缺省或为空数组 = 该源全部 skill 生效**（与既有目录级声明完全兼容，既有 `.dsh/skill-references.yml` 无需迁移）；`skills` 一旦列出名字，则**只有列出的生效**。
- **异常处理**：`skills` 含重复名 → 去重后按一份处理；含不存在的名 → 该名不生效且不影响其他。

### 关闭一个 skill 时白名单如何生成

- **场景**：某条目的 `skills` 缺省（全量生效）时，用户关闭该源下的 skill `beta`。
- **行为**：把「关闭时刻该源发现的全部 skill 名 − 被关闭项」写入该条目的 `skills`；即关闭动作把该条目从「全量跟随」转为「显式清单」。
- **异常处理**：该源当前不可用（invalid/empty）→ 无从取得全量清单，此时开关禁用（不可切换），不产生空白名单把整源意外关死。

### 停用与同名回退

- **场景**：停用引用源 A 的 skill `x`，而目标工作区本地 `.dsh/skills` 也有同名 `x`（此前被引用源 rank=1 压制）。
- **行为**：停用 = 该源**不再提供**该 skill；生效聚合里不再占用 `x` 这个名字，本地同名按既有 rank 规则自然回退生效，预览区该卡片来源标注随之变为「本地」。
- **异常处理**：多个引用源都含 `x` 且靠前者被停用 → 回退到下一个仍含 `x` 的引用源，再退到本地。

### 源新增 skill 的行为（白名单的必然结果）

- **场景**：某条目已设置白名单，源工作区此后新增 skill `gamma`。
- **行为**：`gamma` 不在清单内 → **默认不生效**，并在面板中以「停用灰显」卡片出现，供用户按需打开。该源由「纯跟随」变为「显式清单跟随」。
- **异常处理**：用户在面板把 `gamma` 打开并保存 → 名字写入白名单，随即生效。

### 开关与编辑态

- **场景**：用户切换某个开关。
- **行为**：切换**即时**反映视觉（灰显/恢复），同时改动落入编辑态副本并计入 dirty；点「保存并应用」才写回目标工作区声明文件并触发该工作区重发现；点「取消」丢弃编辑态、开关回到已保存状态。
- **异常处理**：保存失败 → 保持编辑态与开关现状，以错误条呈现，不回滚用户改动、不写坏文件。

### 开关作用对象

- **场景**：预览区里的本地 skill。
- **行为**：只有**来自引用源**的 skill 有开关；本地 skill 无开关（白名单只存在于声明条目，本地无承载位置）。
- **异常处理**：无。

### 视觉规格（不自造元素）

- **场景**：实现开关与置灰。
- **行为**：开关按官方 Switch 规格复刻——`button[role="switch"][aria-checked]` + 一个 thumb `span`；`36×20`、`padding 2`、`border-radius 10`、关态底色 `--dsw-alias-border-l3`、开态 `--dsw-alias-brand-primary`、thumb `16×16` 圆角 50% 用 `--dsw-alias-label-primary-foreground`、开态 `translate(16px)`、`transition transform .12s ease`；`disabled` 时 `opacity .5`，`focus-visible` 用 `2px solid var(--dsw-alias-brand-primary)` 外描边。置灰用 `--dsw-alias-label-dimmed` / `--dsw-alias-label-tertiary`，卡片整体 `opacity 0.4`。
- **异常处理**：官方 token 清单中**不存在** switch 专用 token，故一律取上述语义最接近的官方 token；不新增自造 token 名、不写死色值兜底、不引入组件库依赖（延续「内联样式 + `--dsw-alias-*`」既有约定）。

### 两侧过滤一致性（硬约束）

- **场景**：同一份白名单同时决定「真实 catalog」与「面板展示」。
- **行为**：reference-provider（真实生效）与 source-inspection（面板预览）必须对 `skills` 作出**完全相同**的判定——否则会出现「面板显示已关闭但模型仍能加载」或反之的错位。
- **异常处理**：任一源读取失败 → provider 侧的既有降级语义（该源不贡献候选）与 inspect 侧的 `invalid`/`empty` 三态保持各自既有行为，两者都不得因此把白名单误判为「全量生效」。

## 预设测试

### 前置条件

- 工作区 SRC（开发源）：`D:\dev\skill-dev`，含 `.dsh/skills/alpha/SKILL.md`（name: alpha）与 `.dsh/skills/beta/SKILL.md`（name: beta），均带描述。
- 工作区 B（目标，面板管理对象）：`D:\dev\project-b`，初始无 `.dsh/skill-references.yml`，本地 `.dsh/skills` 为空。
- 主题可在 DSH 设置里切换浅色/深色。

### 测试步骤

1. **[重构后的预览区]**：面板选目标 B，声明引用 SRC 并保存。
   **预期结果**：预览区出现 `alpha`、`beta` 两张卡片；每张**最左侧**是来源标签「skill-dev」，其次 skill 名称，描述最多两行超出省略，最右侧是开态 Switch；不再出现重复罗列 skill 名的 tag 行。
2. **[关闭即时灰显]**：关闭 `beta` 的开关。
   **预期结果**：`beta` 卡片立即整体降透明度、描述与标签变灰，开关为关态；卡片仍在列表中可见；面板转为 dirty，「保存并应用」可点。
3. **[保存后真失效]**：点「保存并应用」。
   **预期结果**：`B/.dsh/skill-references.yml` 该条目出现 `skills: [alpha]`；在 B 打开会话时 skill catalog 中**没有** `beta`（模型不可见、不可加载），`alpha` 正常；重开面板 `beta` 仍为灰显关态。
4. **[重新打开]**：再次打开 `beta` 并保存。
   **预期结果**：`beta` 恢复生效（catalog 可见），面板卡片回到正常态。
5. **[本地同名回退]**：在 B 本地放 `.dsh/skills/beta/SKILL.md`，再关闭引用源 SRC 的 `beta` 并保存。
   **预期结果**：预览区 `beta` 卡片的来源标签变为「本地」且无开关；B 的 catalog 中 `beta` 由本地提供（引用源优先不再压制它）。
6. **[取消可回滚]**：切换任意开关后点「取消」。
   **预期结果**：所有开关回到已保存状态，声明文件未变，dirty 清除。
7. **[深浅色检查]**：在步骤 1–3 的每个状态下切换浅色/深色主题。
   **预期结果**：开关开态、关态、灰显卡片、来源标签、省略号文本在两色板下均正常可读，无白底/黑字错乱。

### 异常场景

- **[源不可用时切换开关]**：把 SRC 目录改名使该源 `invalid` → 该源卡片的开关禁用 → 无法切换，不产生空白名单把整源关死。
- **[白名单含不存在的名]**：手工在声明里写 `skills: [alpha, ghost]` → `ghost` 被忽略、不报错，`alpha` 正常生效，面板不出现 `ghost` 卡片。
- **[声明损坏]**：手工把 `skills` 写成标量（如 `skills: alpha`）→ 面板提示声明解析失败（与既有 `name`/`path` 非法时一致），provider 侧降级为空并 warn，不误写文件。
- **[既有声明兼容]**：目标工作区保留一条无 `skills` 的旧声明 → 该源全部 skill 照常生效，面板开关默认全开（与改造前行为一致）。
- **[源新增 skill]**：SRC 新增 `gamma` 后刷新面板 → `gamma` 以灰显关态卡片出现（不在白名单内），打开并保存后生效。
- **[描述超长/为空]**：源里某 skill 描述极长 → 卡片描述两行省略，卡片高度稳定；描述为空 → 按既有 wire 约束（描述非空）不会出现，若出现则不渲染描述块。

## 边界收束

**此时必做**：

- 声明条目可选 `skills` 白名单，host 侧 schema 校验与 wire contract（host/client 共享 strict descriptor）同步扩展。
- reference-provider 按**逐源**白名单过滤候选（真实生效链）。
- source-inspection 返回逐源全量 skill 及其启用态，生效聚合跳过被停用项（使本地同名回退），供面板灰显与白名单生成。
- 预览区卡片化重构（来源标签前置、描述两行省略、右侧常显开关、关闭项灰显、移除重复 tag 行）。
- 开关纳入既有编辑态（dirty/保存并应用/取消），复用 `replace` 写回与按目标 cwd 的精准失效。

**此时不做**：

- **本地 skill 的停用** —— 白名单只存在于引用声明条目，本地无承载位置；需要时须另设本地停用机制。触发条件：出现「想停用目标工作区自身某个 skill」的需求。
- **逐源整体启停（整源开关）** —— 与删除该声明条目等价，已有能力覆盖；触发条件：出现「想临时保留声明但整体停用某个源」的真实使用。
- **悬浮/悬浮才显形的操作条** —— 本轮按确认结论采用常显 Toggle；触发条件：卡片信息密度进一步上升、常显控件造成拥挤时。
- **声明编辑区与健康度区的重构** —— 本轮重构范围限于预览区；触发条件：用户反馈整个面板的视觉层级仍不统一时。
- **全景关系视图 / 逐源 diff / 目标工作区持久记忆** —— 沿用既有 later-on（`skill-reference-interactive` L01/L03/L05），与本轮无重叠。

## 实现对齐

锚定基线：`.intentflow/_packages/dsh-skills-reference.yml` 与既有三半实现（host 数据/provider、host RPC、client 面板）。

- **[声明承载白名单]**：`src/schema.ts` 的 `ReferenceEntry` 加可选 `skills?: string[]`，`assertEntry` 加「可选 / 必须是字符串数组 / 元素非空」校验；`src/contract.ts` 的 `referenceEntrySchema` 同步加字段（list/replace/inspect 三个 descriptor 的方法签名不变，`replace` 的 entries 自然携带白名单）。
  - **推导出的约束**：✅ `serializeReferences` 走 yaml stringify，可选字段会自然序列化；`skills` 缺省即「全量生效」，既有声明零迁移。测试点：测试步骤 3、异常场景-[既有声明兼容]/[声明损坏]。
  - **design 决策**：白名单为「显式清单」还是另设停用列表（`disabled`）——已定采用清单（与既有 later-on L02 备注一致）。

- **[provider 逐源过滤]**：`src/reference-provider.ts` 需按「候选来自哪个引用源」应用该源白名单。当前实现把全部源目录合并进一个内层 `FileSystemSkillProvider`，候选上不带来源归属，**必须新增归属判定**。
  - **推导出的约束**：✅ 官方 `SkillCandidate` 带 `path?: string`（绝对文件路径），可按解析后的源目录前缀归属；官方 `FileSystemSkillProvider` 支持 `customSkillDirs`，也可每源建一个内层实例。两条路都验证可行。测试点：测试步骤 3（真失效）/5（同名回退）。
  - **design 决策**：归属判定方式——逐源内层实例（干净但实例/watcher 数×源数）vs 按 `candidate.path` 前缀归属（省实例但有路径规范化边界）。
  - **design 决策**：白名单过滤落在「内层 list 之后」还是「`get` 也要二次校验」（防白名单在发现后被改动时的穿透）。

- **[inspect 承载停用项]**：`src/source-inspection.ts` 与 `src/contract.ts` 的 `inspectSkillSchema` 扩展为「逐源全量 skill + 启用态」；生效聚合在既有 `byName` 循环里**跳过被停用项**，本地同名即自然 push 回退。
  - **推导出的约束**：✅ 既有逻辑已是「引用源先填 `byName`、本地兜底跳过同名」，跳过停用项即得到所确认的同名回退语义，改动最小。测试点：测试步骤 5、异常场景-[源新增 skill]。
  - **design 决策**：返回结构——在现有 `skills` 数组上加 `enabled: boolean`（并把被停用的候选也放进数组）vs 新增独立字段承载停用项。
  - **design 决策**：用**声明条目索引**还是源展示名/源路径把预览项绑定回条目——同名源（两个条目名字相同、路径不同）下按名字绑定会歧义，索引或路径更可靠。

- **[面板卡片与开关]**：`src/client/panel.tsx` 预览区改为卡片渲染（来源标签前置、描述两行省略、右侧官方规格 Switch、停用项 `opacity 0.4` + dimmed 文本、删除 `tagRowStyle` 的重复 tag 行）；`src/client/controller.ts` 承载开关切换（即时视觉 + 落入 `entries[i].skills` 编辑态 + dirty；源不可用时开关禁用）。
  - **推导出的约束**：✅ 开关复用既有 `dirty`/`save`/`reset` 语义，不新增半保存状态；样式继续用内联 `CSSProperties` + `--dsw-alias-*` token。测试点：测试步骤 1/2/6/7。
  - **design 决策**：白名单生成时机——切换时立即算出并写入编辑态副本，vs 保存时统一由停用集合反推。
  - **design 决策**：全部打开时是否把 `skills` 清空回「缺省=全量」，以保持声明文件简洁。
  - **design 决策**：停用项在列表中的位置与分组（按源分组内混排、还是生效在前/停用置后）。

- **[写回与失效]**：`replace` 携带白名单写入后，沿用既有「按目标 cwd 精准失效 provider」链路即时重发现，无需新增 RPC。
  - **推导出的约束**：✅ 既有 `invalidateFor(cwd)` 已按目标路径失效，白名单变更与路径变更走同一条链。测试点：测试步骤 3 的「保存后 catalog 立即不含 beta」。

与预设测试的关系：白名单承载与过滤（步骤 3/4/5）、卡片重构与开关（步骤 1/2/6/7）、边界与降级（异常场景 6 条）、两侧一致性（步骤 3 与异常场景-[源新增 skill] 同时覆盖真实生效与面板展示）均有对应测试点。
