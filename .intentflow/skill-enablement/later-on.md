# 后续想法备忘：skill 引用启停（skill-enablement）

> 设计阶段识别但**此时不做**的事项，以及未来可能的演进方向。只记录想法，不做任何设计预留——需要时直接实现。

## 想法列表

- **L01**：预览区按来源分组渲染。
  - 现状：本轮 D-06 定为「生效项在前、停用项置后」的扁平列表；同一源的两张卡片可能被分隔在列表两端。
  - 何时做：引用源数量变多、用户反馈「想按源成组地扫一遍并批量判断」时。
  - 备注：只改 `source-inspection` 的聚合顺序（按源分组、组内生效在前），client 按返回顺序渲染即可；另可顺带把逐源健康度并入对应来源分组（即需求中未被采纳的那个布局选项）。
- **L02**：client 组件拆分（`src/client/skill-card.tsx`）。
  - 现状：D-07 让 `SkillPreviewCard`/`SkillSwitch` 与样式常量都留在 `panel.tsx`（本轮后约 520 行）。
  - 何时做：`panel.tsx` 超过约 600 行，或出现第二个消费者需要复用卡片/开关时。
  - 备注：拆分时把该组样式常量一并迁出；`SkillSwitch` 是纯呈现组件，无 controller 依赖，拆分无接口改动。
- **L03**：编辑态即时预览（对未保存的 entries 直接 inspect）。
  - 现状：`inspect(targetPath)` 只读**磁盘上**的声明；因此编辑态新增/删除声明条目后，预览区不刷新（仍是上次保存后的结果），必须保存才能看到新源的效果。
  - 何时做：用户反馈「加了个引用得先保存才知道有没有 skill」时。
  - 备注：需给 `inspect` 增可选 entries 入参（wire 变更），或新增只读的「按给定 entries 预演」RPC；届时要一并处理 D-09 的 `entryPath` 回绑在「未保存条目」下的匹配。
- **L04**：`reference-provider.list` 透传官方 `SkillProviderObservation.complete`。
  - 现状：既有实现把 observation 降级为候选数组、丢弃 `complete`，incomplete 的发现结果会被当作完整结果返回（既有事实，本轮按偏差节「不动」处理）。
  - 何时做：出现「源目录扫描未完成时预览/目录给出半截结果」的实际问题。
  - 备注：逐源化之后实现很直接（任一 slot 返回 incomplete → 整体返回 `{candidates, complete: false}`），但会改变 catalog 不被缓存的既有行为，需一并评估影响面。
- **L05**：本地 skill 的停用。
  - 现状：白名单只存在于引用声明条目，本地 skill 无承载位置，故本轮无开关（需求已划定为「此时不做」）。
  - 何时做：出现「想停用目标工作区自身某个 skill」的需求。
  - 备注：需另设承载机制（工作区本地停用清单）并在 provider 侧过滤本地候选；与 `skills` 白名单是两套语义，不要复用声明条目字段。
- **L06**：逐源整体启停（整源开关）。
  - 现状：本轮只有单 skill 开关；整体停用某源等价于删除该声明条目，已有能力覆盖（需求已划定为「此时不做」）。
  - 何时做：出现「想临时保留声明但整体停用某个源」的真实使用。
  - 备注：语义上等价于 `skills: []`… 注意当前 `skills: []` 被定义为「全量生效」（D-03），故整源停用需要新语义（如 `enabled: false` 条目字段），不能借用空数组。
- **L07**：声明条目 `skills` 白名单的直接查看与编辑。
  - 现状：`skills` 字段只能通过预览区的 skill 开关间接产生与修改；面板不展示该字段本身。
  - 何时做：用户在声明文件里手写了白名单、希望在面板里看到并直接修正时（尤其白名单含源中不存在的「幽灵名」——目前只在用户操作该条目时被顺带清理）。
  - 备注：属声明编辑区的展示能力（本轮重构范围限于预览区）；可复用 D-02 的 `isSkillAllowed` 做一致性判定。

## 与当前设计的关系

- L01 落在 `source-inspection` 的聚合顺序，不改 wire、不改 client 结构；当前不为它预留排序参数。
- L02 是纯文件拆分，不改任何接口；当前不预留组件导出。
- L03 会改变 `inspect` 的签名（wire 变更），与 D-09 的 `entryPath` 回绑耦合；当前不预留在席参数。
- L04 改变 `reference-provider.list` 的返回分支（数组 vs observation），会影响「incomplete 不缓存」的行为；当前保持既有降级。
- L05 新增一套本地停用语义与承载，与 D-02/D-03 的白名单判定**并存**（两者都汇入 provider 的过滤层）；当前不为它预留字段。
- L06 需要新条目字段来区分「空数组=全量」与「整源停用」，与本轮 D-03 的语义直接相关；当前不预留。
- L07 只增声明编辑区的展示，复用既有判定函数；当前不预留 UI 位。
