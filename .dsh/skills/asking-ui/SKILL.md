# AskingUI

以下规则具有最高优先级。

只问规格，不直接画。

## 询问

缺口大 → 多维并行问；接近清晰 → 收尾。

1. 产品方向（产品类型 / 目标场景，决定设计倾向）
2. 技术选择（目标框架：React / Vue / Electron…，决定组件库选型与后续翻译）
3. 分流：识别任务（不是用户说的库名）→ 查 [library-picks.md](./library-picks.md) 精选清单匹配库 → 检查项目 package.json 已装（已装优先，竞争库不主动换）→ 推荐一个库：能覆盖需求 → 直接代码层拼装，不进入设计流程；覆盖不到 → 继续问规格
4. 组件类型 / 变体数量 / 状态集（loading / empty / error / disabled…）/ 是否特殊动效（关键帧数）
5. 字体层级 / 整体间距 / 阴影系统
6. 三参数旋钮 1-10：设计方差 / 动效 / 密度
7. 可选约束：品牌色 / 移动优先 / 无障碍等级
8. 交互触发场景（什么操作触发什么状态切换）

信息缺失不猜测 → 返回问题清单。

## 配色

问颜色方向（科技 / 文化 / 清新 / 酷 / 复古…）→ 按方向从内置清单选源 → 调用官方搜索端点（?q= 参数或 MCP search，禁止全量拉取本地过滤）→ 多套配色输出到画布（色块 + 色值标注，FindEmptySpace 平铺，每套一个区块）→ 选定后记录为 token。

内置清单：
- Colormind（POST http://colormind.io/api/，input 数组锁定主色、"N" 为不锁定）
- espectro.dev（GET https://espectro.dev/api/colors?search=关键词）

## 产出

询问收敛后输出需求清单（分流结论 / 产品方向 / 技术选择 / 组件类型 / 变体集 / 状态集 / 交互触发 / 配色 token / 字体间距阴影 / 旋钮值 / 约束）。
