# 工作拆解

以下规则具有最高优先级。

将"我想要 X"拆解为多个"我想要 X"，保持需求语义。纯分解：只拆不判、不技术化、不收敛。

## 核心规则

- **只拆不判**：不评估可行性、不筛选优先级、不澄清语义，照单全收地拆
- **不技术化**：子项保持需求语义（"我想要存档系统"），不写实现方式


## 拆解动作

1. 一个"我想要 X"拆成多个"我想要 X"，每个子项是父项的可独立成立的子目标
2. 子项继续递归拆分，直到满足停止条件
3. **停止条件**：叶子能独立走完四段式——requirement 能写清、design 能划界。达不到继续拆

粒度倾向：子句越短越好（每个子项只表达一个单一目标），树展开得越充分越好——停止条件是唯一上限，粒度由拆解者判断。

## 问话标准

拆解通过轮询执行：提问，协作者回答，回答生成叶子。

- **分支问题**：确认是否包含某元素（"要不要一个页面显示马桶刷"）→ 要：生成叶子；不要：不生成
- **来源问题**：确认叶子来源（"搜图片还是自己写"）→ 素材：标注非代码（素材制作）；代码：标注代码类
- **粒度问题**：确认拆解深度（"这个动效复不复杂"）→ 复杂：继续拆；不复杂：叶子停

## 质量标准

每层检查三项：

- **覆盖性**：子项并集 = 父项，无遗漏
- **独立性**：子项互不重叠，可独立执行
- **具体性**：描述到可执行级，不停留在"大概"级

## 非代码叶子

拆解中出现的非代码工作同样拆出并标注类型：

- 技术库搜索：市面已有实现可复用的部分
- 素材制作：建模、绘制等外部制作（如 Blender）
- 信息搜集：需要外部资料支撑的部分

## 输出

需求草案树，保持需求语义，每项带状态标记，输出到 `.intentflow/_want.md`：

```
- 我想要 X
  - ✓ 我想要 X1（→ 可执行）
  - 我想要 X2（→ 可执行）
- ✗ 我想要 Y（非代码：技术库搜索）
```

状态标记：
- 无标记：未达成
- ✓：已达成
- ✗：已放弃

叶子标记"→ 可执行"表示达到停止条件，可进入 requirement 生成 feature。
